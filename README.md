## 📁 Organización del repositorio

| Carpeta | Contenido |
|---|---|
| `PRACTICA-1/` | Material de consulta, ejercicios, código VHDL, imágenes y reporte de la primera práctica. |
| `PRACTICA-2/` | Material de referencia y espacio para el desarrollo de la segunda práctica. |
| `PRACTICA-3/` | Material de referencia y espacio para el desarrollo de la tercera práctica. |

Dentro de cada práctica se procura separar:

- **Material:** instructivos, manuales y documentos proporcionados para la actividad.
- **ParteN:** archivos fuente VHDL y archivos del proyecto de Quartus correspondientes a cada ejercicio.
- **images:** capturas, diagramas y evidencias visuales.
- **reporte:** documento fuente en LaTeX y, cuando corresponda, el PDF generado.

## 🧑‍💻 Flujo de trabajo y responsabilidades

### Estudiante
- Realizar los ejercicios y las pruebas en el entorno de laboratorio.
- Compartir en el repositorio el código fuente, diagramas, capturas y demás evidencias disponibles.
- Revisar el reporte propuesto y señalar correcciones o información que deba incorporarse.

### Asistente de documentación (ChatGPT)
- Revisar el README, las instrucciones de la práctica y los archivos disponibles antes de redactar.
- Analizar los archivos `.vhd`, `.tex`, configuraciones y evidencias para describir los diseños.
- Elaborar y mantener el reporte en LaTeX con redacción técnica, estructura clara, figuras, fragmentos de código y conclusiones sustentadas.
- Mejorar la documentación general del repositorio cuando sea pertinente.
- Trabajar en una rama independiente y entregar los cambios mediante un Pull Request para revisión.

### Criterios obligatorios
1. **No inventar resultados:** una simulación, compilación o prueba física solo se reportará como realizada si existe evidencia verificable.
2. **Distinguir evidencia de análisis:** el comportamiento deducido del código debe identificarse como análisis del diseño, no como resultado experimental.
3. **Señalar faltantes:** si no hay capturas, archivos fuente, instrucciones o datos suficientes, se indicará expresamente en el reporte y en el Pull Request.
4. **Conservar el material original:** no eliminar ni reemplazar evidencias o proyectos de Quartus sin una razón justificada y revisión.
5. **Revisión antes de integrar:** los cambios se proponen mediante Pull Request; el estudiante revisa y decide si se integran a `main`.

## 📝 Convenciones para los reportes

- Fuente editable en `.tex`.
- Figuras almacenadas dentro de la carpeta `images` de la práctica correspondiente.
- Código VHDL presentado como fragmentos o archivos fuente vinculados.
- Secciones diferenciadas para objetivo, desarrollo, resultados, observaciones y conclusiones.
- Los resultados deben corresponder a capturas o datos realmente disponibles.
